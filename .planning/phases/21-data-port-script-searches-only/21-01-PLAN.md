# Plan 21-01 - Idempotent Searches Port Script

## Objective

Create and test the one-way `searches` data port from SQLite to Postgres.

This plan is data-destructive on the target Postgres `searches` table by
design. The script must fail closed unless the operator explicitly confirms
the truncate/load operation from the CLI. It must never touch users, sessions,
rate limits, Redis cache, or quota history.

## Tasks

1. Implement or harden `scripts/port_searches.py`.
   - No `from __future__ import annotations`.
   - CLI requires an explicit destructive confirmation flag before `TRUNCATE TABLE searches`.
   - Accept both `postgresql://` and `postgresql+asyncpg://` database URLs.
   - Source table only: SQLite `searches`.
   - Target table only: Postgres `searches`.
2. Use `asyncpg.copy_records_to_table` in 1000-row batches.
   - Stream SQLite rows with `fetchmany(batch_size)`.
   - Do not load the full table into memory.
3. Apply all type fixups.
   - SQLite ISO text timestamp -> timezone-aware `datetime` -> Postgres `TIMESTAMPTZ`.
   - CSV/string/list `modules_run` -> `TEXT[]`.
   - Integer/null `success` -> `BOOLEAN`, defaulting legacy null to `true`.
   - Missing/null/invalid payload -> `{}` for Postgres `JSONB`.
   - Count fields default missing/null values to `0`.
4. Assert SQLite count equals Postgres count after load.
   - Raise non-zero failure on mismatch.
   - Log/print only counts and elapsed time, not search queries.
5. Verify idempotency by rerunning against test Postgres.
   - First run loads fixture rows.
   - Second run truncates and reloads same rows.
   - Destination row count remains equal to source count.
   - Sample migrated row has expected converted types.
6. Add tests in `tests/test_port_searches.py`.
   - Helper parser unit tests.
   - Temp SQLite fixture with multiple `searches` rows.
   - Live Postgres integration test using existing `tmp_db`/`TEST_DATABASE_URL`.
   - Skip only when test Postgres is unavailable, matching existing fixture policy.
   - Test destructive confirmation guard.
7. Write `21-01-SUMMARY.md`.
   - Files changed.
   - Commands run and outputs.
   - Row-count parity result.
   - Idempotency result.
   - Any remaining risks.

## Acceptance Criteria

- `rg -n "from __future__ import annotations" scripts/port_searches.py tests/test_port_searches.py` returns no matches.
- `pytest tests/test_port_searches.py -q` passes with live test Postgres available.
- `port_searches.py` exits without modifying Postgres when confirmation flag is absent.
- `port_searches.py` uses `copy_records_to_table` and batch size `1000`.
- `TRUNCATE TABLE searches` occurs only after explicit confirmation.
- SQLite count equals Postgres count after load.
- Rerun against same Postgres target is idempotent.
