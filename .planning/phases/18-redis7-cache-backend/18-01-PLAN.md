    - Fake Redis failure during `get()` returns `None` when fail-open is enabled and increments errors.
    - `stats()` returns keys `backend`, `reachable`, `hits`, `misses`, `errors`, `entries`.

    Create `api/cache.py`:
    - `CacheStats` dataclass with fields `backend: str`, `reachable: bool`, `hits: int`, `misses: int`, `errors: int`, `entries: int | None`.
    - `InMemoryCacheBackend` with async `startup`, `shutdown`, `get`, `set`, `stats`.
    - `RedisCacheBackend` using `redis.asyncio.from_url(REDIS_URL, decode_responses=True, socket_connect_timeout=1, socket_timeout=1)`.
    - Stable key function using `sha256(query.lower().strip().encode("utf-8")).hexdigest()`.
    - JSON serialization via `json.dumps(..., separators=(",", ":"), ensure_ascii=False)`.
    - Enforce `CACHE_MAX_VALUE_BYTES` before `setex`.
    - Use `setex(key, ttl, payload)` for TTL writes.
    - Catch concrete exceptions only: `redis.exceptions.RedisError`, `json.JSONDecodeError`, `TypeError`, `ValueError`, and timeout/socket exceptions if needed. Do not use broad `except Exception`.
    - Fail-open `get` returns `None` on Redis/JSON errors when `CACHE_FAIL_OPEN=true`.
    - Fail-open `set` returns without raising on Redis/JSON errors when `CACHE_FAIL_OPEN=true`.
    - When `CACHE_FAIL_OPEN=false`, re-raise cache startup/get/set failures after incrementing the error counter.
    - Module singleton `cache_backend` defaults to `RedisCacheBackend()`.
    - Constructor should allow a fake/client factory injection for deterministic unit tests without a live Redis server.

    - In shutdown before final log, call `await cache_backend.shutdown()`.
